# 领取邮件

任务入口为 `CollectMail`，显示名称为“领取邮件”。
流程在 `assets/resource/pipeline/mail.json`，模板在 `assets/resource/image/Mail/`。

## 使用方式

先运行“启动并登录”或手动进入游戏主界面，再执行“领取邮件”。
也支持从展开的菜单、信箱列表或已领取道具的确认页开始。
设备与分辨率要求同[启动并登录](./startup.md)：16:9 横屏，短边缩放至 720。

```powershell
python -X utf8 tools/run_startup.py --adb-path 'E:\Program Files\Netease\MuMu\nx_main\adb.exe' --address 127.0.0.1:16384 --task CollectMail
```

脚本整段运行上限为 10 分钟，日志目录为 `debug/mail-run/`。
Ctrl+C 停止操作；只有到达 `MailComplete` 才报告领取完成。

## 流程

1. 打开菜单，识别右下角“信箱”图标，等图标区域稳定后检查未读红色角标。
2. 有未读角标时进入信箱，选择没有“已开封”标记的邮件。
3. 游戏在打开邮件时领取附件；识别“已领取以下道具”和“确认”，点击确认。
4. 关闭信箱，重新打开菜单检查剩余未读邮件，继续领取。
5. 信箱未读角标消失后按返回键关闭菜单，确认主界面菜单与地图按钮恢复，再结束。

已领取邮件会保留在信箱里，不会被删除。重新打开信箱后，本次实测中未开封邮件排在前面。
流程通过卡片的空白状态栏和底边结构区分未开封邮件，不依赖标题、日期、附件图标或金额。
识别使用相关性匹配，避免大块白色背景使已开封邮件被误识别为未开封。
可见区域没有命中未开封邮件，且首个可见邮件状态明确显示“已开封”时才向下翻页；
重新打开信箱会回到列表顶部。这一正向检查避免在列表尚未加载时翻页跳过新邮件。

“没有未读角标”的反向识别节点只会在菜单信箱图标已经被正向识别之后进入。
信箱加载中的暗色画面不会触发打开邮件、关闭信箱或翻页。
任务不会通过“当前页没有邮件”或“没有看到领取按钮”直接宣告完成。

打开未读邮件和翻页各最多 100 次，导航及确认节点最多 103 次；每阶段等待有 10～60 秒上限。
达到操作上限或遇到未知画面后会失败并保留现场，不会把部分领取报告为全部完成。

## 素材与验证

采集日期 2026-09-05；MuMu 5.27.6.3562；游戏 3.15.60（512）；MaaFramework 5.12.3。
原始截图 2560×1440，模板来自框架输出的 1280×720 截图。

信箱未读角标区域为 `[1212, 550, 41, 39]`，使用 RGB 颜色范围识别红色，
不依赖数字本身；菜单稳定等待覆盖整个信箱按钮区域。

本次实机领取了 5 封邮件的附件：采集时手动领取 1 封，自动流程领取其余 4 封。
最后一封领取后，流程确认未读角标消失并回到主界面。再次从主界面运行时，
没有进入信箱，直接确认无未读并正常返回。
未开封邮件按纵向位置优先选择，最终顺序规则通过真实截图验证。
截图回放验证了领取后返回、无未读直接结束、已开封邮件排除、加载中不翻页，
以及翻页达到保护上限后失败。maa-tools 和本地 Pipeline / Interface Schema 校验通过。

特殊邮件无附件、道具容量不足、账号断线、超过单次保护上限的大量邮件及其他屏幕比例尚未验证。
这些情况下不保证自动处理，需要按实际画面补充规则。
