# 猫咪日记

GUI 任务“猫咪日记”从主界面或已打开的日记页开始，读取三个猫槽位的线索，匹配地点后传送，
通过展开的区域地图追踪羽毛图例，在场景内点击羽毛按钮。每次交互后重新读取全部三项任务，
继续处理猫的新地点，直到三个槽位都出现红色完成爪印。

## 使用

- 国服、ADB 控制器、16:9 横屏，控制器缩放截图为 1280×720。
- 已解锁目标地点的传送点；开始前退出战斗、世界地图和其他功能页。
- GUI 可选择 15、45（默认）、90 分钟运行上限；超时后保留现场并报告失败。
- 移动目标需要及时截图，MuMu 使用客户端自动检测出的截图和输入方式。
- 任务不按固定“每只猫两次”或印章数量判断完成，某只猫可以在一次交互后结束。
- 印章卡包含礼物位置上的第七枚；满卡后下一次交互会从新卡第一枚开始，不作为每日刷新。
- 上方倒计时属于当日日记，下方倒计时属于印章奖励。跨过当日日记的期限时停止追踪旧线索。

```powershell
python -X utf8 tools/run_startup.py --adb-path 'E:\Program Files\Netease\MuMu\nx_main\adb.exe' --address 127.0.0.1:16384 --task CatDiary
python -X utf8 tools/test_cat_diary.py
```

命令行使用默认 45 分钟上限，日志位于 `debug/cat-diary-run/`。
退出码 0 要求执行到 `CatDiaryComplete`，失败为 1，Ctrl+C 停止为 130。
GUI 资源更新后需要重新运行 `tools/package_gui.py`，使 Agent、地点数据、模板和任务选项一起进入运行包。

## 实现与资料

| 文件 | 职责 |
| --- | --- |
| `assets/resource/pipeline/cat_diary.json` | 日记、地图、确认框、图例、对话与完成态识别，以及点击和滑动动作 |
| `agent/cat_diary.py` | 三槽位状态、地点消歧、道路规划、移动目标追踪、进度复核 |
| `agent/data/cat_diary.json` | 用户提供的两张地点对照表，共 76 条；实机补充文字变体和传送名称 |
| `agent/data/cat_diary_maps.json` | 实际道路中心线、横向斜坡、地图定位锚点及图例遮挡时的有限搜索点 |
| `tools/test_cat_diary.py` | 地点消歧、刷新、超时、停止、路径与确认框边界验证 |
| `tools/fixtures/cat_diary_stamps.npz` | 实机印章卡局部样本，覆盖 5 枚、第 7 枚和换卡后第 1 枚 |

图片素材来自用户提供的日记、地点对照表、羽毛图例，以及 2026-09-07～10 的 MuMu 实机截图。
用户图片中的表格作为地点资料使用。模板基准为 1280×720；场景内羽毛按钮会随景深缩放，使用多尺寸模板。

新增线索时录入有区分度的原文片段，`world_names` 收录实际世界地图及确认框中出现的完整名称。
不要仅凭相似文字决定目的地。OCR 可能把城镇前缀和名称分成多个框，确认框第一行按横坐标合并后，
必须与允许的完整目的地一致，且同时识别“是否确定”和“是”按钮才点击。
确认文字先按亮色过滤，避免遮罩后方的城市标签被 OCR 拼进确认内容。
单行确认文本过滤高度不足正文一半的独立 OCR 小碎片，避免埃尔吉昂句末标点被读成“2”；
正常字号的数字仍保留，完整目的地匹配要求不变。
区域图标题先过滤亮色文字，再按横坐标合并，避免背景纹理混入文字，或“影之镇”和“纳兹里克”因 OCR 框高度差而顺序颠倒；
纳兹里克补充实机标题 OCR 的“茲”字变体，仅用于落地地图名校验。
点击 OCR/模板识别框的中心，避免框外留白导致随机点击落空。选择时代前先检查选中标记，
当前时代已选中时不重复点击；时代标记与广域入口使用对亮度敏感的模板方法，排除确认框遮罩后的背景。
冥峡界从“???”时代的广域地图进入，识别“冥峡界”分区后再选择目的地，沿用完整传送确认校验。

## 寻路与退出条件

右上小地图随镜头移动，不能将其屏幕坐标当成世界坐标。每一步都展开区域图，有整体平移时先用固定图例校正，
重新识别角色环和移动中的羽毛，关闭地图后短距离滑动，再核验地图名和实际位移。
已录入地图使用道路中心线；其他地图尝试从同一机位主界面与展开图的差分提取道路，
只在识别出的图例遮挡范围内连接已有道路两端，或连接已定位的角色与同轴可见路面。
移动后优先复用此前已产生正确位移的同图道路，避免角色环遮住路口时改走绕路、离开后又折返；
旧道路无法规划或移动受阻时重新使用本帧道路，猫的位置仍逐帧更新。
路口处横向误差不超过 8px，且后续是超过 8px 的纵向连接路时直接换道，避免最短横移越过路口。
路宽内的短折线不作为换道口，远离路口时仍先横向接近。
路径不连通时停止，不直线穿越空白区域。

纳兹里克本次只标定东侧传送点到猫所在道路的连接路段，西侧和其他路线未标定。
其两段斜坡经实机确认由左右输入通过，按实际坡面录入 `horizontal_slopes`，不把像素路径的台阶当成上下换道。
该地图还会随坡面高度整体纵移，使用固定心形图例将角色和猫的位置还原到标定坐标；
锚点不可见、横向偏差超过 8px 或纵向偏差超过 45px 时停止定位，不沿用错误坐标。

已标定地图会排除道路附近以外的角色环候选，防止背景灯笼被当成角色。
关图后若角色已接近羽毛、或羽毛与其他图例重叠而漏识别，会再次检查场景内的交互按钮。
加达洛已观察到羽毛被任务图例长时间遮住，允许沿已确认道路访问一个已观察到猫的搜索点 `(422,392)`；
仍逐步重新识别移动羽毛，抵达搜索点不代表成功。该点用尽仍未找到羽毛或交互按钮时，按四帧缺失保护停止。
搜索点仅对有道路中心线的指定地图生效，与普通追踪共用步数、无位移、用户停止和时间上限。

地点库覆盖范围不等于全部地图都已实测。冥峡界目前验证纳兹里克入口，冻时领域东西侧、跨区域出口、楼层切换尚未验证；
未解锁传送点、无法匹配的线索、看不到羽毛、无法确定道路或角色位置时，任务报告原因并保留现场。
未知场景的自动道路提取仍需更多实机验证。

每个地点最多 240 次定位移动，连续三步没有预期位移即停止。每轮最多 24 次猫事件，
每次普通对话最多 20 页；只处理已识别的普通对话、公告、战斗攻击和结算页。
所有截图和操作检查用户停止状态、任务上限及当日日记期限。

日记读取要求连续两次三槽位状态一致；单个槽位读不到文字不代表该猫结束。
每次交互都复核任务或印章的实际变化；仅接受已观察到的 `7 → 1` 满卡换新卡，其他印章减少仍停止。
完成的猫重新变成待找状态或任务与印章均没有变化时停止，满卡换卡也不能绕过每日刷新期限和槽位重置保护。
完成节点再次独立识别日记标题、面板、可见的关闭键与三个红爪印，避免 Python 动作返回成功但游戏任务未完成。
