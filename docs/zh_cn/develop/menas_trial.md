# 梅纳斯试炼

任务标识和入口为 `MenasTrial`，显示名称为“梅纳斯试炼”。
流程位于 `assets/resource/pipeline/menas_trial.json`，模板位于 `assets/resource/image/MenasTrial/`。
`agent/menas_trial.py` 负责参数、入场券读取和逐场计数，已接入 Agent 与命令行注册。

右下角的谜晶鉴定另由[梅纳斯谜晶鉴定](./menas_appraisal.md)任务处理，支持白值、词条筛选和自动锁定。

## 使用方式

先运行“启动并登录”，或手动进入可操作的游戏主界面，再运行“梅纳斯试炼”。
也可以从活动列表、梅纳斯试炼选关页开始。

- 可输入 **0～999** 次，默认 **0**，表示用完本次开始时持有的全部梅纳斯入场券。
  每场挑战 **STAGE SS**，消耗 **1 张梅纳斯入场券**；正数按指定次数执行。
- 玩家需提前配置能够通关的队伍、技能和游戏内相关预设。
- 任务不编辑、切换队伍，不选择技能，不切换 REPEAT、倍速、逃跑、搭档或 Another Force。
- 任务不购买入场券。指定次数多于持有量时，完成可用票数后停止并报告实际次数；
  因未达到指定次数，任务返回失败。全部模式零票时直接返回主界面并正常结束。
- 游戏、分辨率和账号条件与[启动并登录](./startup.md)相同。

命令行调试沿用已有脚本，增加任务参数：

```powershell
python -X utf8 tools/run_startup.py --adb-path 'E:\Program Files\Netease\MuMu\nx_main\adb.exe' --address 127.0.0.1:16384 --task MenasTrial --count 0
```

脚本默认仍执行 `StartUp`。读取初始票量后，试炼运行总预算按实际计划场数 ×15 分钟设置；
每个阶段仍受下述识别等待和点击次数限制。
日志目录为 `debug/menas-trial-run/`。Ctrl+C 会停止自动操作，不会自动退出游戏里的战斗。

## 流程与完成条件

1. 点击底部活动按钮，再点击“梅纳斯试炼”横幅；已在选关页时直接读取。
2. 同时识别试炼标题与右侧独立的 `SS` 字样。对左下“入场券持有量：数量/上限”连续读取两次，
   数量一致才继续；零票时关闭选关页。确认可用票数后点击 STAGE SS。
3. 识别“进行挑战”并点击一次，等待进入战斗。
4. 同时识别右下角“攻击”和左上角“状态确认”，仅点击攻击。
5. 识别“获得道具”结算页，点击中部空白区域推进经验结算。
6. 识别 `Congratulations` 后，等待中央任务列表和奖励弹层连续稳定 800 毫秒再点击，
   推进 Cleared、战斗奖励和逐条通关条件展示。稳定检测覆盖 `[360, 235, 565, 335]`，
   不使用始终可见的标题判断动画是否结束；每次最多等待 10 秒，持续光效导致等待超时时
   按框架行为继续本次点击，再识别下一状态，保留单场 16 次点击上限。
7. 结算之后，底部菜单和地图按钮同时恢复为正常亮度，才到达 `MenasTrialComplete` 并计入一场。
8. 尚有计划次数时重新进入选关页，核对票量恰好减少 1；变化异常即停止。全部模式以初始票量为上限。

主界面完成节点仅能从结算链到达；进入任务时看见主界面会开始导航，不会直接报告完成。
结算弹窗优先于主界面识别，避免透过弹窗遮罩提前结束。达到计划次数后停在主界面，不再打开活动。

每场开始时重置相关节点的命中计数：导航按钮最多命中 3 次；提交挑战最多 1 次；攻击最多 100 次；道具结算最多 8 次；
通关提示最多 16 次。导航每阶段等待 30～60 秒，入场和战斗每阶段等待 180 秒，
结算每阶段等待 60 秒。攻击次数是操作保护上限，不等于游戏回合数。
识别不到下一状态或超出命中上限后会超时失败，不会无条件继续点击。

## 本次观察到的战斗与结算界面

- 等待操作时，左上角显示状态确认、REPEAT、倍速和逃跑按钮；下方显示角色、技能名称和 HP/MP。
- 点击攻击后，角色执行玩家保存的技能。技能动画中攻击按钮与左上角控制按钮消失，
  因此等待其重新出现即可进入下一轮，无需识别伤害、敌方血量或技能过程。
- 顶部显示 Another Force 等战斗条，右侧有搭档相关按钮，当前流程不操作这些控件。
- 胜利后左上角显示“获得道具”“经验值”，下方显示角色等级与经验条。
- 离开经验结算后返回场景，出现 `Congratulations / Cleared` 和战斗奖励，
  然后逐条展示通关条件。每次点击可能只推进一条，需要继续识别提示标题。
- 标题在 `Mission Reward` 弹层和任务达成动画期间仍然可见，动画中的点击可能无效。
  因此标题只作为结算页识别条件，点击前还需对中央内容执行 `pre_wait_freezes`，
  匹配阈值 0.99、采样间隔 100 毫秒，避免连续空点耗尽保护上限。

模板只截取按钮和固定文字，不依赖队员头像、技能名称、奖励数量、活动日期或加成角色。
STAGE S 与 SS 的蓝色底板高度相似，因此 SS 模板仅包含两个 S，并使用相关性匹配；
不能用大面积蓝色底板的相似程度区分关卡。

### 2026-09-11 结算失败修复

用户运行包日志显示：战斗已胜利，但 `Congratulations` 标题在奖励动画期间持续可见，
原流程约每 0.48 秒点击一次，7.2 秒内耗尽 16 次上限，随后停在 `Mission Reward` 弹层超时失败。
使用运行包的独立 Python Agent、MaaFramework 5.12.3 和 MuMu ADB `127.0.0.1:16384`，
指定 `count=1` 实机复现了相同问题。

修复仅增加结算中央区域的静止等待，不提高点击上限，不改动战斗、票数和完成条件。
先用修复后的结算节点完成复现时卡住的一场，再通过同步后的运行包完整执行一次 `count=1`：
攻击 2 次、通关结算点击 6 次，确认 `MenasTrialComplete` 与 Agent 成功返回。
前五次静止检测在约 1.8～3.4 秒内完成；末页持续光效使最后一次达到 10 秒等待上限，
随后点击并正常返回主界面。该有界等待不会将动画期间的连续空点计满。

本次排查和验收合计消耗 2 张入场券，票量从 3 降至 1，最终重新读取确认并返回主界面。
录屏式连续截图、节点时间、失败现场和验收结果保存在 `debug/menas/2026-09-11/`。
13 项梅纳斯单元测试、maa-tools 和本地 Pipeline / Interface Schema 校验通过。

新增多场循环与零票返回尚未实机消耗验证。战败、网络断线、角色升级额外弹窗、活动改版与其他屏幕比例尚未实测；
