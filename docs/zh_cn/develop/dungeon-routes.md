# 副本扫荡路线

本页记录点击队伍页“跳过”后的路线菜单；普通进入副本后手动行走的岔路不属于本配置。

## 客户端配置

在“副本跳过”中选择红票或绿票副本后，有扫荡分支的副本会显示“副本名 · 扫荡路线”下拉框。
红绿票分别使用自己所选副本的路线。各副本的设置独立保存，切换副本不会把上一副本的路线套用过来。
无旧配置时默认第一条已确认路线；恩特纳默认仍为皱囊虫遗迹。

## 数据与执行

- `agent/data/dungeons.json` 为每个有分支的入口记录 `skip_routes`、`default_route`、`route_evidence`；
  可滚动菜单额外使用 `route_scroll`。路线 ID 不依赖显示顺序，名称校对时应保持已有 ID。
- `tools/update_dungeon_options.py` 为副本 case 生成 `option` 子配置；只在该副本被选中时显示。
  新旧副本选项共用这些路线子配置，路线参数为 `routes: {副本ID: 路线ID}`。
- Maa 5.12.3 的多段覆盖会替换整个 `custom_action_param`，不能直接把不同选项写入同一参数对象。
  生成器为各选项建立独立的 `DungeonSkipOption_*` 节点，将值写入 `attach`；
  `read_interface_options` 在执行前读取并合并，红绿票的路线字典也分别保留。
  资源默认参数通过 `use_interface_options` 启用此过程，CLI 的完整参数覆盖仍走原有解析路径。
- `parse_request` 在执行前验证所选路线属于对应副本，将结果复制到本次请求，不修改原目录。
  已保存的其他副本路线会被保留，但只读取本次目标对应的键；非法当前路线直接拒绝。
- 先确认“请选择区域”标题，再从弹窗列表中精确匹配路线文字并点击对应行。
  只有完整可见、达到置信阈值的文字参与匹配；同名多处、目标缺失、弹窗消失或重复选择均停止。
- 大漩涡目标不在视野时先向上查找至顶部，再向下遍历；每个方向最多十次滑动，并检测画面边界。
  滚动区域位于列表内部，避开取消按钮。每次滚动后重新识别，不能按固定行号点击。
- 区域选择不计入扫荡场次，仍在“获得道具 / 要继续跳过吗”页确认次数。
  连续扫荡沿用游戏已选路线；重新出现选择弹窗时再次按当前配置选择。

命令行可传入 `--red-route`、`--green-route`；旧单副本模式使用 `--dungeon-route`，参数值为目录路线 ID。
红绿票和猫掌券补充开关与路线设置独立，默认仍不补充；不使用克洛诺斯之石。
